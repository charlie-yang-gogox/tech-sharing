五層完整定義 — 以及台上沒講完的三件事The five rungs in full — and the three things the stage left out

投影片上只留了樓梯跟一句結論。這一頁是那張圖底下的東西：每一層真正管什麼、迴圈有哪三種停法（只有一種算 loop engineering）、以及人類核准閘該擺在哪一條邊上。The slides keep the staircase and one closing rule. This page is what sits underneath that picture: what each rung actually governs, the three ways a loop can stop (only one of them counts as loop engineering), and which edge an approval gate belongs on.

RUNGS

五層，每一層管的東西The five rungs and what each one governs

累加，不是取代cumulative, not replacement
1 PROMPT

你怎麼問。一段字。這一層的全部內容就是那次請求的措辭 — 你要什麼、用什麼格式、不要做什麼。 How you ask. A piece of text. This rung is entirely the wording of one request — what you want, in what shape, and what not to do.

下一層存在的理由：它看不到我的世界。措辭再好，模型手上沒有那份檔案、那張票、那段 log。 Why the next rung exists: it cannot see my world. However well worded, the model does not have the file, the ticket, or the log.

2 CONTEXT

它這一次看到什麼。一次呼叫的完整內容 — 指令、檔案、前面的對話、工具回傳的結果，以及它們的順序與取捨。這一層的工作是選擇：放什麼進去，以及更難的，放什麼不進去。 What it sees this time. One call's whole payload — instructions, files, prior turns, tool results, and the order and trade-offs among them. The work at this rung is selection: what goes in, and harder, what stays out.

下一層存在的理由：它沒有手。脈絡整理得再乾淨，它還是只能講話，不能讀檔、不能跑測試、不能開 PR。 Why the next rung exists: it has no hands. However clean the context, it can still only talk — it cannot read a file, run a test, or open a PR.

3 HARNESS

它周圍有什麼。工具、儲存、狀態、上限、權限。Agent = Model + Harness — 同一個模型換一副 harness 就是另一個 agent。 What surrounds it. Tools, storage, state, caps, permissions. Agent = Model + Harness — the same model in a different harness is a different agent.

下一層存在的理由：每一步都要我按。工具齊了，但它做完一步就停下來等我，所以我變成那個迴圈。 Why the next rung exists: every step needs my keypress. The tools are there, but it stops after each one and waits for me — so I am the loop.

4 LOOP

它怎麼在沒有我的時候自己跑下去。這一層真正的產出物是終止判斷式 — 不是「會重複」，是「怎麼停」。詳見下一節。 How it keeps going without me. The real deliverable at this rung is a termination test — the point is not that it repeats, but how it stops. See the next section.

下一層存在的理由：同時跑，會撞在一起。一個會自己跑的東西很好用；十幾個會自己跑的東西會搶同一個檔案、同一台裝置、同一張票。 Why the next rung exists: they collide when run at once. One self-running thing is useful; a dozen of them fight over the same file, the same device, the same ticket.

5 GRAPH

很多個會自己跑的東西怎麼協作。產出物是顯式拓樸：誰先跑、誰接手、誰決定、在哪裡匯合、哪一條邊要人點頭。迴圈本身就是一張有環的圖，所以它直接掉進別人的一個方塊裡 — 圖是把迴圈包進去，不是取代它。 How several self-running things coordinate. The deliverable is an explicit topology: who runs first, who takes over, who decides, where they join, and which edge needs a human's nod. A loop is just a directed cyclic graph, so it drops straight into someone else's node — a graph absorbs the loop rather than replacing it.

爬到頂不是每個人都該做的事。「大部分的工作根本不需要堆疊的頂端 — 今天很多上了 production 的 agent，正確地說，就只是一段脈絡整理得很好的 prompt 待在一個還不錯的 harness 裡。」這一場的六個 pattern 全部住在最上面那一層，但那是因為講的人的問題長在那裡，不是因為第三層不夠好。 The top of the stack is not for everyone. “Most tasks still don't need the top of the stack — plenty of production-grade agents today are, correctly, still just a well-context-engineered prompt inside a decent harness.” The six patterns in this talk all live on the top rung, but that is because the speaker's problems live there — not because the third rung is inadequate.
STOPPING

迴圈的三種停法 — 只有一種算 loop engineeringThree ways a loop can stop — only one counts as loop engineering

◯

A · 沒有判斷式A · no test at all

做完再做，沒有任何退出條件。它永遠不會停 — 帳單會先告訴你。 Do, then do again, with no exit condition. It never stops — the bill tells you first.

×5

B · 只有次數上限B · a cap and nothing else

繞滿五次就放棄。不會失控，但也不保證做完 — 它停下來的時候，你不知道是成功還是放棄。 Give up after five rounds. Safe, but no promise it finished — when it stops, you cannot tell success from surrender.

✓

C · 真的檢查 + 上限當保險C · a real check, cap as backstop

過了就停，沒過就再一輪，上限只是保險。只有 C 叫 loop engineering。 Pass and stop; fail and go one more round; the cap is only a backstop. Only C is loop engineering.

C那個「檢查」要是真的檢查The check has to be a real one

測試綠了、schema 過了、CI 綠了、review 沒有未解決的討論 — 這些是真的檢查。問模型「你覺得可以了嗎」不是。模型答「可以了」的成本是零，所以那個答案不承載任何資訊。 Tests green, schema valid, CI green, no unresolved review threads — those are real checks. Asking the model whether it feels done is not. Answering “yes” costs the model nothing, so the answer carries no information.

GGC 裡的 /ggx-pr-review-loop 就是 C：review 乾淨且沒有未解決的討論才退出，外加 --max-rounds=5 當保險 — 而且逾時的那一次不計入次數，因為逾時不是一次失敗的嘗試。 GGC's /ggx-pr-review-loop is C: it exits only when the review is clean AND no unresolved threads remain, with --max-rounds=5 as the backstop — and a timed-out attempt does not consume a round, because a timeout is not a failed attempt.

GATES

圖裡最值錢的兩條性質The two properties of a graph worth the most

◻

節點之間互相看不到Nodes cannot see each other

同時跑的方塊各拿乾淨的脈絡，所以一個人的誤判不會傳染給另外兩個。這是圖裡最值錢、也最容易被省掉的一條 — 省掉之後圖還是會跑，只是三個節點會一起錯同一個方向。 Parallel nodes each get fresh context, so one node's misread never infects the others. The most valuable property of a graph, and the first one people skip — skip it and the graph still runs, it just gets all three nodes wrong in the same direction.

✎

人類點頭的位置是設計的一部分Where the human nods is part of the design

核准閘放在後果最集中的那一條邊上，不是平均散在每一步。每一步都問等於沒有閘 — 人會開始一路按 yes，而那一條真的重要的邊就跟其他二十次一樣被按過去。 An approval gate sits on the edge where consequence concentrates, not sprinkled evenly across every step. Asking at every step is the same as having no gate — people start saying yes on reflex, and the one edge that mattered gets waved through like the other twenty.

分層取自四份彼此獨立、但在排序上一致的整理（prompt → context → harness → loop → graph，累加；且迴圈是圖的一個特例）： The rungs come from four independent write-ups that agree on the ordering (prompt → context → harness → loop → graph, cumulative) and on loops being a special case of graphs: Analytics Vidhya, “Agent Harness vs Loop vs Graph Engineering” · Sarthak AI, “Harness, Graph and Loop Engineering” · TrueFoundry, “Graph Engineering for Multi-Agent Systems” · LangChain, “3 Years of Graph Engineering with LangGraph”
