講稿備註 · 這頁要講的（不上投影片）SPEAKER NOTES · what to say on this slide (not projected)

唯一的差別The whole difference — workflow 把好幾個 component 串成一條流程，而那條流程就只是一支 .js。skill 也好、一條普通 flow 也好，差別只有這個 — 計畫住在誰身上。A workflow strings several components into one flow, and that flow is just a .js. Against a skill or any ordinary flow that is the only difference — who holds the plan.

最省事的做法：打一句話The cheap path: type one sentence — use a workflow：這個 PR 改到的每個檔案各派一個 agent 去審，再合成一份排序過的清單。腳本它自己寫。use a workflow to review every file changed in this PR, then merge the findings into one ranked summary. It writes the script itself.

但那通常不是最後的版本But that is rarely the final version — 流程一旦值得留下來，自己定義出來的那條通常更貼近需求。誰先跑、誰接手、哪裡一定要停，這些是規格，不是它猜得到的。Once a flow is worth keeping, one you define yourself usually fits the requirement better. Who runs first, who takes over, where it must stop are specifications, not guesses.

其他叫法Other ways in — 句子裡帶 ultracode；/effort ultracode 讓整個 session 自己決定要不要開；跑順了在 /workflows 按 s，它就變成你自己的 / 指令。Put ultracode in the sentence; /effort ultracode lets Claude decide all session; press s in /workflows and a good run becomes your own / command.

三個原語就是全部Three primitives are the whole vocabulary — agent() 生一個乾淨 context 的 subagent，pipeline() 每個項目各自跑完不互等，parallel() 是「等全部到齊」的柵欄。接下來那六個 pattern 就是這三個的排法。agent() spawns one subagent with a clean context, pipeline() lets each item run without waiting for the others, parallel() is the barrier that waits for all. The six patterns coming up are arrangements of these three.

腳本被擋住的事What the script may not do — 不能 import()（純 JS，要套件就交給 agent）、不碰檔案也不跑指令（那是 agent 的事，腳本只調度）、中途不能問人（要人簽核就切成兩支）。上限是同時 16 個 agent、單次 1000 個。No import() (plain JS; library work goes inside an agent), no filesystem or shell from the script itself (agents read, write and run; the script only coordinates), and no mid-run user input (need a sign-off? make it two workflows). Caps: 16 concurrent agents, 1,000 per run.

Skill 沒有被取代Skills are not replaced — skill 是「指示」，workflow 是「腳本」；可重複的東西不一樣 — skill 重複的是那份指示，workflow 重複的是調度本身。GGC 兩種都在用：lane 裡每一站還是 skill，把 lane 排成圖的是 workflow。A skill is instructions Claude follows; a workflow is a script the runtime executes. What repeats differs: for a skill it is the instructions, for a workflow it is the orchestration itself. GGC runs both — each stop inside a lane is still a skill; what arranges the lanes is a workflow.

存下來之後After you save one — 存進 .claude/workflows/（跟著 repo 走）或 ~/.claude/workflows/（只有自己看得到）。GGC repo 裡那四支 workflows/*.workflow.js 是這條路的終點，不是入場券。It goes to .claude/workflows/ (shared with the repo) or ~/.claude/workflows/ (yours only). The four workflows/*.workflow.js in the GGC repo are the end of that road, not the entry to it.

Classify-and-act

“Use a classifier agent to decide on the type of task, and then route to different agents or behavior based on the task. Or, use a classifier at the end to determine output.”

  • 對到前半段：classifier → route。我們沒有用「最後才分類決定輸出」那一半。The first half only: classifier → route. We do not use the “classify at the end to determine output” variant.
  • 分類器是獨立的一支指令 /route，只印出建議、不改任何狀態 —— 所以四個 orchestrator 共用同一顆。The classifier is its own command, /route: it prints a recommendation and mutates nothing — so four orchestrators share one copy.
  • 它路由的終點是整條 pipeline 而不是一個 agent，一次只走一條。It routes to a whole pipeline, not to an agent, and exactly one lane fires.
  • 我們多加一步（不在 pattern 裡）：label 本身由 haiku 提案 + sonnet 盲審決定，因為錯的 label 會安靜地浪費一整條 pipeline。One step we added (not in the pattern): the label itself comes from a haiku proposal confirmed blind by sonnet, because a wrong label silently wastes a whole pipeline run.

Fan-out-and-synthesize

“Split up a task into many smaller steps, run an agent on each step and then synthesize those results. … The synthesize step is a barrier—it waits for all the fan-out agents, then merges their structured outputs into one result.”

  • 整條對得上，barrier 也在。PM 與 Designer 是同一個 wave 真的並行，synth-agent 等三份 notes 全到才動，合出一份 spec — 這就是原文那句「等所有 agent，再併成一個結果」。The whole shape matches, barrier included. PM and Designer genuinely run in one parallel wave; synth-agent waits for all three notes and merges them into one spec set — exactly the post’s “waits for all the fan-out agents, then merges into one result”.
  • 而我們最大的那個 fan-out 反而刻意拿掉了 barrier。dispatcher 一張票一個 agent，但失敗的那條腿當下就把留言寫回 tracker，其他票還在 build — 不等整批。And our biggest fan-out deliberately drops the barrier. The dispatcher runs one agent per ticket, but a failing leg writes its tracker comment the moment it fails while other tickets are still building — nothing waits for the batch.
  • 敢拿掉的前提正是原文那個字：merges their structured outputs。回傳是 schema 驗證過的物件，不是要人記得的文字摘要 — 所以「先回來的先處理」不會弄丟東西。What makes dropping it safe is the post’s own word — it merges structured outputs. Every return is a schema-validated object, not prose somebody has to remember, so handling them as they land loses nothing.
  • 另一個非要 barrier 不可的地方是看板掃描：「排名最高的前 N 個過關者」在所有判定回來以前根本沒有邊界。有理由才設 barrier，其餘一律 pipeline。The other place a barrier is unavoidable is the board sweep: “the highest-ranked N that pass” has no boundary until every verdict lands. A barrier needs a reason; everything else pipelines.

Adversarial verification — 雙審 panelAdversarial verification — the panel

“For each spawned agent, run a separate spawned agent to adversarially verify its output against a rubric or criteria.”

  • 對到的部分：separate spawned agent —— 實作者永遠不稽核自己的 diff；以及 against a rubric ——「只動到 UI 嗎」「行為變了嗎」就是那份標準。The part we use: a separately spawned agent — the implementer never audits its own diff — and a rubric: “is this UI only?” versus “did behaviour change?”
  • 我們把 N 固定成 2，但兩位釘在不同 model tier，為的是漏判不相關；兩位都 CLEAR 才過，任一 BLOCK 整個 diff 退回。We fix N at 2, but pin them to different model tiers so their misses are not correlated. Both must clear; either BLOCK reverts the whole diff.
  • 我們加的一條：稽核者不准讀實作者整理過的摘要，只准讀原始 payload — 讀了摘要就會繼承同一個盲點。One rule we added: the auditor is denied the implementer’s digest and reads only the raw payloads — a curated view hands it the same blind spot.
  • 而且驗的是宣稱，不只是 code：worker 可以什麼都沒出貨還回報 done。所以查核有三個結果 — confirmed / missing / inconclusive，第三個才是重點。And it verifies the claim, not only the code: a worker can report done having shipped nothing. So the cross-check has three outcomes — confirmed / missing / inconclusive, and the third one is the whole design.

Generate-and-filter

“Generate a number of ideas on a topic and then filter them by a rubric or by verification, dedupe duplicates and return only the highest quality, tested ideas.”

  • 對到後半段：filter by a rubric ＋ dedupe。掃板用四值 rubric，/ggx-demo 用（expected-crux + intent）去重而不是設數量上限。The second half: filter by a rubric plus dedupe. The sweep uses a four-value rubric; /ggx-demo dedupes on (expected-crux + intent) rather than capping a count.
  • 而且過濾器不一定要是模型：/spec-lint 九項 grep，零次模型呼叫，同時抓漏寫與幻覺。And the filter need not be a model: /spec-lint is nine grep checks, zero model calls, catching both omission and hallucination.

Tournament

“Instead of dividing the work, have agents compete on it. Spawn N agents that each attempt the same task using different approaches. Prompts or models then judge the results in a pairwise fashion using a judging agent until you have a winner.”

  • 最接近的是雙審 panel 與雙票分類 —— 但那是同一個答案審兩次，不是「幾個答案裡選一個」。形狀不同，別混為一談。The nearest things are the dual-judge panel and the 2-vote classifier — but those judge one answer twice. They never produce a second answer to choose from.
  • 真的可能划算的位置：衝突解決、難的 bug fix（今天是第一個看起來合理的做法直接贏）。原文的排序實例也把成本講白了：每一場比對都是一個新 agent。Where it might pay: conflict resolution and hard bug fixes, where today the first plausible fix wins. The post’s sorting example states the cost plainly: every comparison is its own agent.

Loop until done

“For tasks with an unknown amount of work, loop spawning agents until a stop condition is met (no new findings, or no more errors in the logs) instead of a fixed number of passes.”

  • 對到的部分：停止條件而不是固定次數 —— test-fix-loop 跑到全綠，不預設幾輪。The part we use: a stop condition instead of a fixed number of passes — test-fix-loop runs until the suite is green, with no preset round count.
  • 我們加的第三個出口：不收斂就停。失敗集合跟上一輪一樣、而且沒有任何修改 → 中止並說出是哪道防護（外加 max-iters 8 的硬上限）。The third exit we added: stop when it is not converging. Same failing set as last round AND no edit applied → abort and name the guard (plus a hard max-iters 8).
  • 同一形狀還有四處：ui-tweak 回修（≤3 次）、PR review loop、/port:revise、/ggx-work 的 route→執行→再 route。Four more places share the shape: the ui-tweak repair loop (max 3), the PR review loop, /port:revise, and /ggx-work’s route → run → route again.

講稿備註 · 這頁要講的、五個花錢學到的坑（不上投影片）SPEAKER NOTES · what to say, and five edges each paid for by a real run (not projected)

不用記名字You do not have to remember the names — 要接一條流程的時候，真正在決定的只有這三題 — 這一章的標題就是它們：誰先跑、誰接手、誰決定。When you wire a flow these are the only three questions you are answering — they are this chapter’s title: who runs first, who takes over, who decides.

為什麼剛好是三塊Why exactly three — Anthropic 的 Building Effective Agents 把 agent 流程歸成三個基本積木（Prompt Chaining · Routing · Parallelization）加兩個進階組合（Orchestrator-Subagents · Evaluator-Optimizer）。六個 pattern 全部落在其中三塊。剩下那兩塊 GGC 也有，只是不算在這六個裡：Prompt Chaining 就是每條 lane 本身，Orchestrator-Subagents 就是 dispatcher 那一層。Anthropic’s Building Effective Agents groups agent workflows into three basic blocks (Prompt Chaining · Routing · Parallelization) plus two advanced ones (Orchestrator-Subagents · Evaluator-Optimizer). All six land on three of them. GGC uses the other two as well — Prompt Chaining is each lane itself; Orchestrator-Subagents is the dispatcher layer.

Pattern 之於 workflowPatterns are to workflows — 就跟 design pattern 對程式一樣 — 串法早就有人歸納好了，不用每次重新發明。what design patterns are to code — the ways of wiring are already catalogued; you never have to invent one.

args 其實是字串arrives as a string — 傳真的陣列進去，腳本收到的還是 JSON 文字。更重要的是把「空 roster」跟「有帶東西但 parse 成 0 列」分開：後者一個 agent 都沒生，看起來卻跟乾淨的 no-op 一模一樣。A live array still reached the script as JSON text. And separate “empty roster” from “carried work, parsed to zero rows” — the second spawns nothing and looks exactly like a clean no-op.

沒有時鐘，也沒有隨機No clock, no randomness — Date.now() 和 Math.random() 在腳本裡會直接丟錯，因為那會弄壞 resume。run key 和時間戳由呼叫端先鑄好再傳進去。Date.now() and Math.random() throw inside a script — they would break resume. Run keys and timestamps are minted by the caller.

摘要可能根本不會回來A summary can simply not arrive — 一個 agent 把整件事做完、拍完、發布完，orchestrator 只收到一則 idle 通知。沉默被讀成「什麼都沒發生」，於是重跑一次，變成重複。結構化回傳是機制；「記得先讀 tracker」只是散文。An agent built, captured and published its whole job; the orchestrator got only an idle notification. Silence read as “nothing happened”, so the recovery was a duplicate. Typed returns are a mechanism; “re-read the tracker first” was prose.

腳本不准放判斷The script holds no judgement — 曾經有 120 行的 rubric 以 JS 字串住在腳本裡，那是一條過期規則能躲過每一次清理的唯一原因。它被刪掉，不是改掉：現在每個 agent 只拿到一個 stage 檔。A 120-line rubric copy lived as a JS string and was the only reason a stale rule survived every cleanup. It was deleted, not edited.

長文用路徑回傳Return prose by path — note 內文、報告都以檔案路徑回傳，因為我們量到過沒有上限的欄位在傳輸中被截斷。短的結構化值才過邊界，文件留在磁碟上。Note bodies and reports come back as file paths — an unbounded field was measured being truncated in transport.

巢狀 spawn 看父層怎麼生出來Nesting depends on how the parent was spawned — Workflow 腳本生出來的 agent 沒有 Agent 工具，不能再往下生一層 — 前面每一張圖的形狀都是被這條限制決定的。要嵌套就得換成 headless claude -p，而且每次 Claude Code 更新都要重測。An agent spawned by a Workflow script has no Agent tool and cannot spawn its own — that shaped every diagram here. Real nesting needs headless claude -p, re-probed after every Claude Code update.

14 / HERDR

很多 session 散在很多個 CLI 裡，會迷路Many sessions across many CLIs is how you get lost

關掉視窗也不迷路 — 側欄告訴你誰在等你CLOSE THE WINDOW AND YOU ARE NOT LOST — THE SIDEBAR SAYS WHO IS WAITING

herdr.dev · workspace / tab / pane + sidebar states working / blocked / idle / done  ·  右圖是示意，沒有真實專案名right side is stylized, no real project names

SPEAKER NOTES

When this is the tip. More than one project, and more than one session under a project. Plain terminal tabs do not tell you which agent is waiting.

What herdr is. A terminal multiplexer rebuilt around coding agents. A background server owns the real terminals. Workspaces hold tabs and panes. A sidebar rolls up each agent as working, blocked, idle, or done. Close the lid, drop SSH, come back — the herd is still there.

The figure. Left is the failure mode: four CLIs, no shared status. Right is a drawn herdr chrome, not a screenshot of my machine. Names are fictional on purpose.

What I would say next if asked. Persistence, the title-as-status, and that agents can drive the same CLI. Do not put a live 18-pane dump on this page unless we decide the real snapshot belongs here.
