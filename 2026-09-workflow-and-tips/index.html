一句話One message — 每一階會存在，是因為下面那一階留下了一個問題。Each rung exists because the one below it left a problem behind.

不要把樓梯唸出來，用走的Do not read the staircase out — walk it — 從最下面那一階開始，講踢面不要講踏面 — 踢面才是論證。Start at the bottom step and say the riser, not the tread — the risers are the argument.

  • PROMPT — 你怎麼問。一段字。PROMPT — how you ask. A piece of text.
  • 「它看不到我的世界」→ 所以 CONTEXT。措辭再好，模型手上沒有那份檔案、那張票、那段 log。“It cannot see my world” → so CONTEXT. However well you word it, the model does not have that file, that ticket, that log.
  • 「它沒有手」→ 所以 HARNESS。脈絡整理得再乾淨，它還是只能講話。“It has no hands” → so HARNESS. However clean the context, all it can still do is talk.
  • 「每一步都要我按」→ 所以 LOOP。工具齊了，但它做完一步就停下來等我 — 所以我變成那個迴圈。“Every step needs my keypress” → so LOOP. The tools are there, but it stops after each step and waits for me — so I am the loop.
  • 「同時跑，會撞在一起」→ 所以 GRAPH。一個會自己跑的東西很好用；十幾個會搶同一個檔案、同一台裝置、同一張票。“They collide when run at once” → so GRAPH. One thing that runs itself is useful; a dozen of them fight over the same file, the same device, the same ticket.

The GRAPH column is drawn out of five slabs, the PROMPT column out of one. graph 不是新東西 — 它只決定兩件事：誰先誰後、結果怎麼匯合A graph is nothing new — it decides only two things: what runs first, and how the results merge

迴圈本身就是一張有環的圖，所以它可以直接當別人的一個方塊。圖不是取代迴圈，是把迴圈包進去 — 前面四層都在這個框裡面，一層都沒有被換掉。A loop is itself a graph with a cycle, which is why it can be somebody else’s single box. A graph does not replace the loop, it absorbs it — all four rungs below are inside this frame, and not one of them was swapped out.

唯一值得堅持的一句The one thing worth insisting on — 那個「檢查」要是真的檢查：測試綠了、schema 過了、CI 綠了、review 沒有未解決的討論。不是問模型「你覺得可以了嗎」 — 模型答「可以了」的成本是零，所以那個答案不承載任何資訊。That check has to be a real check: tests green, schema valid, CI green, no unresolved review threads. Not asking the model “do you think it is done?” — answering “yes” costs the model nothing, so the answer carries no information.

台上只留這一句The only line that stays on stage — 框外面的路是你畫的；框裡面要不要再繞一輪，是它當場決定。The route outside the box is yours; whether to go round again inside it is its own call.

節點之間互相看不到Nodes cannot see each other — （舊版這是收尾卡，現在只用講的）同時跑的方塊各拿乾淨的脈絡，一個人的誤判不會傳染。要補上它為什麼值錢：省掉它圖還是會跑，只是三個節點會一起錯同一個方向。(This used to be the takeaway card; now it is spoken only.) Boxes that run at the same time each get clean context, so one of them going wrong does not infect the others. Add why that is worth paying for: drop it and the graph still runs — it just means three nodes go wrong in the same direction together.

  • A 沒有判斷式 — 永遠不會停，帳單先告訴你。A, no condition — it never stops; the bill tells you first.
  • B 只有次數上限 — 不會失控，但它停下來時你分不出成功跟放棄。B, a round cap only — it cannot run away, but when it stops you cannot tell success from giving up.

07 / THE VEHICLE

腳本可以叫它寫；但誰先跑、誰接手、哪裡一定要停，是你定的IT CAN WRITE THE SCRIPT; WHO RUNS FIRST, WHO TAKES OVER AND WHERE IT MUST STOP ARE YOURS

講稿備註 · 這頁要講的（不上投影片）SPEAKER NOTES · what to say on this slide (not projected)

唯一的差別The whole difference — workflow 把好幾個 component 串成一條流程，而那條流程就只是一支 .js。skill 也好、一條普通 flow 也好，差別只有這個 — 計畫住在誰身上。A workflow strings several components into one flow, and that flow is just a .js. Against a skill or any ordinary flow that is the only difference — who holds the plan.

最省事的做法：打一句話The cheap path: type one sentence — use a workflow：這個 PR 改到的每個檔案各派一個 agent 去審，再合成一份排序過的清單。腳本它自己寫。use a workflow to review every file changed in this PR, then merge the findings into one ranked summary. It writes the script itself.

但那通常不是最後的版本But that is rarely the final version — 流程一旦值得留下來，自己定義出來的那條通常更貼近需求。誰先跑、誰接手、哪裡一定要停，這些是規格，不是它猜得到的。Once a flow is worth keeping, one you define yourself usually fits the requirement better. Who runs first, who takes over, where it must stop are specifications, not guesses.

其他叫法Other ways in — 句子裡帶 ultracode；/effort ultracode 讓整個 session 自己決定要不要開；跑順了在 /workflows 按 s，它就變成你自己的 / 指令。Put ultracode in the sentence; /effort ultracode lets Claude decide all session; press s in /workflows and a good run becomes your own / command.

三個原語就是全部Three primitives are the whole vocabulary — agent() 生一個乾淨 context 的 subagent，pipeline() 每個項目各自跑完不互等，parallel() 是「等全部到齊」的柵欄。接下來那六個 pattern 就是這三個的排法。agent() spawns one subagent with a clean context, pipeline() lets each item run without waiting for the others, parallel() is the barrier that waits for all. The six patterns coming up are arrangements of these three.

腳本被擋住的事What the script may not do — 不能 import()（純 JS，要套件就交給 agent）、不碰檔案也不跑指令（那是 agent 的事，腳本只調度）、中途不能問人（要人簽核就切成兩支）。上限是同時 16 個 agent、單次 1000 個。No import() (plain JS; library work goes inside an agent), no filesystem or shell from the script itself (agents read, write and run; the script only coordinates), and no mid-run user input (need a sign-off? make it two workflows). Caps: 16 concurrent agents, 1,000 per run.

Skill 沒有被取代Skills are not replaced — skill 是「指示」，workflow 是「腳本」；可重複的東西不一樣 — skill 重複的是那份指示，workflow 重複的是調度本身。GGC 兩種都在用：lane 裡每一站還是 skill，把 lane 排成圖的是 workflow。A skill is instructions Claude follows; a workflow is a script the runtime executes. What repeats differs: for a skill it is the instructions, for a workflow it is the orchestration itself. GGC runs both — each stop inside a lane is still a skill; what arranges the lanes is a workflow.

存下來之後After you save one — 存進 .claude/workflows/（跟著 repo 走）或 ~/.claude/workflows/（只有自己看得到）。GGC repo 裡那四支 workflows/*.workflow.js 是這條路的終點，不是入場券。It goes to .claude/workflows/ (shared with the repo) or ~/.claude/workflows/ (yours only). The four workflows/*.workflow.js in the GGC repo are the end of that road, not the entry to it.
