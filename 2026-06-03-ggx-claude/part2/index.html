💡 1. Proposal

The WHAT & WHY. 定義核心需求、user story、嚴格驗收標準，在寫 code 前鎖定範圍。 Defines core requirements, user stories, and strict acceptance criteria to lock in feature scope before coding begins.

🛠️ 2. Design

The HOW. 技術架構、DB schema、API 契約，防止整合風險與幻覺。 Maps out technical architecture, database schemas, and API contracts to prevent integration risks and hallucinations.

✅ 3. Tasks

The EXECUTION. 拆成可勾選的 step-by-step checklist 與 atomic commit。 Breaks the design into step-by-step checklists and atomic commit plans for real-time progress tracking.

🧠 The Context Dilemma🧠 The Context Dilemma

Higher Context = Lower Accuracy

長對話會讓 LLM 失焦、忽略指令、產生幻覺。 Long dialogues cause LLMs to lose focus, ignore instructions, and generate hallucinations.

解法：分散式 ContextSolution: Distributed Context

把任務分給多個 agent，讓每個 context window 都保持小而乾淨。 Split tasks among agents to keep each context window small and clean.
