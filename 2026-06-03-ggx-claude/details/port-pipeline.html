WHY

為什麼是這個形狀？Why this shape?

三個關鍵設計決策three core design decisions
01 dev 一定先跑（Wave 1）dev runs first (Wave 1)

PM 跟 designer 在沒看 origin codebase 之前什麼都會講對——把不存在的 component 當成已存在的，把舊架構假設成新的。dev-consult-agent 跑完 Locate gate（deterministic file/symbol 檢查）給後面兩個 agent 一條「現實基準線」。 Without reading the origin codebase first, PM and designer will confidently get everything right — treating components that don't exist as if they do, assuming old architecture is new. dev-consult-agent's Locate gate (deterministic file/symbol checks) hands the next two agents a reality baseline.

先 ground，再發散。grounding 是 hallucination 的疫苗。Ground first, diverge after. Grounding is the vaccine against hallucination.
02 PM 與 designer 必須平行（Wave 2）PM and designer must run in parallel (Wave 2)

同一份 dev-notes 進、不同檔案出，沒有 data dependency——能平行就一定要平行。實作上是 /port:plan 在同一個 message 裡發兩個 Agent tool call，不是兩個 message。 Same dev-notes in, different files out, no data dependency — if it can be parallel, it must be. In practice, /port:plan issues two Agent tool calls in the same message, not two messages.

「同一個 message 裡 spawn」是平行的物理條件，不是優化技巧。"Spawn in the same message" is the physical requirement for parallelism, not an optimization trick.
03 synth 不能平行（Wave 3）synth cannot be parallelized (Wave 3)

輸入是三份 notes 的 union、輸出之間有 dependency（proposal → design → tasks → specs）。一個 agent 拿全部 context 一次寫完，比較容易維持一致性。 Input is the union of three notes; outputs have dependencies (proposal → design → tasks → specs). One agent writing it all in one pass with full context keeps things consistent.

能平行就平行；不能平行就承認，硬拆只會生 inconsistency。Parallelize where you can; admit it where you can't — forcing it only breeds inconsistency.

PM 寫 FR-N / AC-N、designer 寫 A-N、synth 把它們 cite 進 spec。任何下游 agent 都能倒推「這段來自哪個 requirement / assumption」。 PM writes FR-N / AC-N, designer writes A-N, synth cites them into the spec. Any downstream agent can trace "which requirement / assumption did this come from?"

🤝

TAKEAWAY

記住這四件事Remember these four things

分享結束如果只能帶走幾句話if you only walk away with a few lines
  1. State 存 filesystem，不存 memory——每個 stage 都有 artifact，中斷、重跑、被 dispatcher 接手都行。 State lives in the filesystem, not memory — every stage leaves an artifact, so interrupts, reruns, and dispatcher handoffs all just work.
  2. 先 ground，再發散——Wave 1 的 dev-notes 是 hallucination 疫苗。 Ground first, diverge after — Wave 1's dev-notes is the hallucination vaccine.
  3. 能平行 = 同一個 message 裡 spawn——Wave 2 兩個 agent 必須同 message 同 turn，否則就是序列。 Parallel = spawn in the same message — Wave 2's two agents must be in the same message, same turn, or you're back to serial.
  4. OpenSpec 是 agent 間的中介語言——結構化、可 lint、有 traceability，下游 /dev:* 才能無縫接手。 OpenSpec is the lingua franca between agents — structured, lintable, traceable; that's what lets /dev:* downstream pick up seamlessly.
