1 為什麼要記Why measure

「AI 幫我做事」是直覺，但幫我做了多少、花了多少錢、比手做省了多少時間——沒記就沒結論。"AI helps me get things done" is a gut feeling — but how much, at what cost, how much time saved vs doing it by hand? No data, no conclusion.

看不到Invisible
prompt 效率Prompt efficiency
turn 數越少代表 prompt 越精準fewer turns means tighter prompts
看不到Invisible
省下多少時間Time saved
AI active hours vs 手做的 story-point estimateAI active hours vs the manual story-point estimate

場景：同一張票同一個人，這次跟下次比，cost 漲了 30%、turn 數翻倍——是 prompt 變差還是任務變難？沒數字就只能憑感覺，有數字才能在 retro 時拿出來看。Scenario: same ticket, same person, this run vs next — cost up 30%, turn count doubled. Worse prompt or harder task? Without numbers it's all vibes; with numbers you have something to bring to retro.

## Session Metrics · CAF-198 · 2026-05-13

### Numbers
| Metric              | Value           |
|---------------------|-----------------|
| Total cost          | $3.42           |
| Cost per turn       | $0.21           |
| Turns               | 16              |
| Cache hit rate      | 78%             |
| AI active time      | 47 min          |
| Story-point est.    | 3 (1 day)       |
| Time saved          | ~7.2 hours      |

### Summary
- Cost efficiency: $0.21/turn is below the 30-day avg ($0.28) — prompts were tight.
- Cache hit 78%: above the 70% baseline; the long figma receipt was reused 4 turns.
- Agent ROI: dev-agent ran 12 min for $1.40, produced 380 LOC + 3 test files. Worth it.
- Prompt efficiency: 16 turns for a 3-SP ticket — good ratio.
- Action: cache hit dropped on turn 11; figma re-fetch on a stale URL. Pin the URL.

4 Takeaway

  1. 沒記就沒結論：「我感覺今天 AI 幫了我很多」不是 retro 能拿來用的東西。Cost、cache、turn、time saved 才是。No data, no conclusion: "I feel like AI helped me a lot today" isn't something retro can use. Cost, cache, turn, time saved — those are.
  2. Story-point sticky：同一張票第一次跑問一次 SP，之後沿用。一個小設計避免每次都被 prompt 打斷。Story-point sticky: ask for SP once on the first run per ticket, reuse afterwards. Small design choice that keeps prompts out of the way later.
  3. 跨 session 算總帳：dispatcher / sub-agent 跑掉的 token 預設不會算進主 session，skill 支援把分散的成本聚合起來——別讓總成本被「藏」在另一條 session。Aggregate across sessions: dispatcher / sub-agent tokens don't roll into the main session by default; the skill aggregates the scattered costs — don't let the total cost get "hidden" in another session.
  4. CSV 才是真資產：單次報告會被 ticket 蓋過，但 CSV 累積三個月後，可以做 cost-per-SP trend、模型成本分布、cache 命中曲線——這些是 monthly retro 的素材。The CSV is the real asset: a single report gets buried by the next ticket, but three months of CSV gives you cost-per-SP trends, model cost distribution, cache-hit curves — the raw material for monthly retro.
  5. 跟 Linear 綁定：報告貼回 ticket 而不是分開的 dashboard，因為「ticket 才是工程師事後翻回去看的地方」。Bind it to Linear: reports go back onto the ticket, not into a separate dashboard — because "the ticket is where engineers actually go back to look."
