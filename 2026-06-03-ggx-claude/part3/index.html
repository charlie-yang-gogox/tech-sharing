Pro Tips · 實戰心得Pro Tips · field-tested takeaways

這陣子用下來的觀察 what I've learned running this in production
★ TIP 01

別追求 100% 自動化Don't chase 100% automation

AI 第一步走錯，後面全部 cascade 浪費——ticket 沒對齊 → spec 寫錯 → 解錯題、白燒幾小時。多設幾層 human review，每層 2–5 分鐘，把錯誤攔在還便宜的地方，比讓 AI 一路衝到 QA 才發現划算多了。判斷題留給人，重複動作交給系統。 If AI drifts at step 1, the next 8 steps cascade into wasted work — misaligned ticket → wrong spec → wrong feature, hours burned. A few human review layers, 2–5 min each, trap errors while they're still cheap. Far better than letting AI sprint to QA before anyone notices. Humans own judgment; the system owns the repetition.

★ TIP 02

Cache 成本是隱形殺手Cache cost is the silent killer

長 context × 多 turn = O(N²) 累積，每個 turn 都 cache-read 整段上下文，量大後每 turn 都在燒。另外 cache TTL 預設只有 5 分鐘，idle 過了下一輪 cache miss，同段 prompt 成本 ×12.5（0.1× → 1.25×）。實務做法：長任務直接拆 session、用 sub-agent 把 worker 的長 context 跟 orchestrator 隔開；做到一半別離開鍵盤喝咖啡。 Long context × many turns = O(N²) accumulation — every turn cache-reads the entire context, so once it's big, every turn burns. Plus cache TTL defaults to 5 minutes — idle past it and the next turn is a cache miss, costing ×12.5 the same prompt (0.1× → 1.25×). Mitigation: split long tasks into separate sessions, use sub-agents to isolate the worker's long context from the orchestrator; don't idle mid-task.

★ TIP 03

workflow 要持續 review 自己Keep reviewing your own workflow

最大的改進來自重看 workflow 本身，甚至可以丟給 AI 幫你找浪費點： The biggest gains come from re-reading the workflow itself — you can hand it to AI to find the waste:

  • 模糊指令 → 包成 skill 減少 turn 數 vague prompts → wrap into a skill to cut turn count
  • format / PR 等雜事不要在 main session 跑，丟 sonnet / haiku chores like format / PR shouldn't run in the main session — hand to sonnet / haiku
  • Main session 當指揮官 spawn agent 隔離 context，避免 long context 與主觀污染 treat main session as commander, spawn agents to isolate context — avoid long-context bloat and self-bias
  • 持續觀測 cost & 追蹤效率，把協作表現數據化——每次 session 跑 /session-metrics 留紀錄，/monthly-summary 把它累積進 Notion 當 ground truth；月底看趨勢：cost 漲 / cache hit 跌 / turn 爆 都是改進訊號 measure cost & efficiency continuously — make collaboration data-driven: run /session-metrics each session, let /monthly-summary aggregate into Notion as the ground truth; read monthly trends — rising cost, dropping cache hit, or spiking turns are all improvement signals

gogox-claude · 平行運轉、整隊共用的 AI workflow 系統gogox-claude · a parallel, team-shared AI workflow system

這套 pipeline 真正想解決的不是「AI 寫更多 code」，而是「把工程師的時間從重複動作裡撈回來」。Worktree 讓平行成立、dispatcher 把 Linear queue 自動派工、spec gates 把幻覺攔在進 dev pipeline 前、code-review routine 把 baseline 守住——這些都是「該系統做的」，不該讓人類手動。 What this pipeline really solves isn't "AI writes more code" — it's "getting engineer time back from repetitive motions". Worktrees make parallelism possible, the dispatcher fans out the Linear queue, spec gates trap hallucinations before they reach dev, and the code-review routine holds the baseline — all things the system should do, not a human.

另一邊，四個 ★ DEV HUMAN GATE 是「不該交給 AI」的開發精華地帶——ticket 細節、spec 對齊、AI review 過濾、真人 review。判斷題留給人，重複動作丟給系統。Overview 那條 pipeline 是這條路徑的骨架；Part B 是黏合 pipeline 的工具；Part C 則是不綁 pipeline、純粹給個人 / 任何專案用的通用 skill，把成本 / 產出 / 時間都量化下來。 On the other side, the four ★ DEV HUMAN GATEs are exactly where dev judgment belongs — ticket detail, spec alignment, filtering AI review, human review. Judgment stays with humans; repetition goes to the system. The Overview pipeline is the skeleton; Part B is the connective tissue; Part C is the repo-agnostic personal layer that quantifies cost, output, and time saved.

如果整場分享只記得一句話：「該人做的別讓 AI 做，該 AI 做的別讓人做。」剩下的都是這句話的工程化展開。 If you take one line from this talk: "Don't make AI do what only humans should, and don't make humans do what AI can." The rest is just engineering around that single idea.
